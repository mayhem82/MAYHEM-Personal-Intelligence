CLARITYPATH — PUBLIC APPLICATION BUILD GUIDE
© 2026 Julian Minko · Architect of MAYHEM · ClarityPath

This guide describes the public ClarityPath application and its reproducible public files. Julian Minko’s supplied MAYHEM specifications are private build inputs. They are not included, licensed, offered for download or authorised for redistribution by this site or pack. Do not retrieve them from old commits, copies or caches. Do not add them to a source library or artificial intelligence request.

## 0. Complete setup for the new owner
Read setup.html for the readable manual, coding-assistant and trusted-person routes. Put accounts, costs, permissions, privacy, recovery, device requirements and implementation limits first. Begin with GitHub account creation and optional coding-artificial intelligence connection; distinguish that setup assistant from the required artificial intelligence inside ClarityPath. AI-SETUP.txt and MANUAL-SETUP.txt are complete copy/download versions, each including the shared start-here material. Source documents are in setup/ and SETUP-FOR-NEW-OWNER.txt. Keep operating.html readable too.
When this repository or pack is supplied for cloning/installation, the receiving artificial intelligence must carry out SETUP-FOR-NEW-OWNER.txt. It is a complete installation task: establish the recipient’s account and destination, create/use their own public application repository and a separate private case-data repository, deploy their site, configure encryption and independent recovery, deploy/connect required artificial intelligence under their control, test the real authorised connections with synthetic data and publish the matching Build pack. Root AGENTS.md makes this task visible to coding agents working from a clone.
Use the source project as a reference. Configure the new owner’s actual Git remote, branch, Pages URL, service origin, endpoints and private credentials. Keep their case records and private settings out of the public site. Preserve the creator attribution. Complete independent work while any owner-controlled authentication, private credential entry or applicable charge approval is pending; identify the exact remaining blocker and keep installation marked incomplete until its required connections are genuinely verified.

## 1. Reproduce the public application
Use the exact public source files and image bytes in build-pack.txt. Text blocks are UTF-8 with LF line endings. Image blocks marked ENCODING: base64 must be decoded to bytes; the recorded hash and byte count refer to decoded bytes. The pack contains the working application, not a separate prefilled demonstration.
Preserve the creator notice, Disclaimer page, source attributions and public/private boundary. Installing for a different private-data owner does not transfer the creator’s attribution or rights in private MAYHEM material.
Run node scripts/package-release.mjs, then npm test. With the declared Playwright development dependency and a supported browser, run npm run test:e2e, npm run test:pwa, npm run test:navigation, npm run test:mental-health and npm run test:launch, plus npm run test:installation. Package only the explicit public manifest. Do not upload workspace attachments, private build inputs, backups or credentials.

## 2. Public situations and sources
Home is the installed application’s starting and returning page. Choosing Open my workspace or Workspace opens the populated New South Wales situation catalogue, independent of saved private cases. It includes applicable Commonwealth-law reading sources. Provide Area of law and a complete Choose a situation dropdown directly beneath it. Search and area filters affect the entire dropdown, not only the paginated browsing cards. Choosing a situation displays its guide, topic reading links, bodies, contacts and sourced escalation information.
Keep official guide titles and attribution. Explain whether source text is included or opened at the external source. Preserve mandatory, conditional and direct routes, prior decisions/referrals/notices, evidence, timing, exemptions and source check dates. Do not invent a universal escalation ladder or claim complete coverage of all law.
The public legal source library contains public legal references only. Private product specifications must never appear there or become selectable case material.

## 3. Private workspace and required artificial intelligence
The application records separate cases, original accounts and files, chronology, links, review, sources, summaries and selected handoffs. Keep original material and later interpretation separate. Corrections are additive. Preserve the implemented validation, case isolation, checksums and encryption behaviour when replicating.
Temporary in-memory work needs a save or download. Encrypted device saving, private GitHub storage and required artificial intelligence assistance have separate setup. Use a private repository owned by the actual case owner, a restricted token and an encryption passphrase. Never put secrets or case data in the public repository, source pack or logs.
The artificial intelligence service receives only the reviewed, selected payload. Do not append private specifications or unrelated project documents. Provider credentials stay on the owner-controlled server. Installation or a GitHub connection is not permission to transmit case data or private build material to an artificial intelligence provider.
Do not change or reconstruct private MAYHEM definitions from memory. Work requiring private reference material must use it locally under its owner’s explicit authorisation; that authorisation does not permit publishing or transmitting it.

## 4. Installation, publishing and verification
Keep the supplied homepage logo, launcher icons, relative-scope manifest, installed Home launch and return behavior, and Install app control. Use a native install prompt where available and accurate manual instructions otherwise. Cache only the named public application resources; exclude private data, authenticated requests and external/application programming interface calls. Do not erase encrypted device data when updating public resources.
Publish the explicitly staged site/ output through the included Pages workflow. Before publication, verify that public files and pack contain no private specifications or extracts. Old restricted source paths must not return the original documents. Keep Build separate from the workspace; it contains this public application guide and public source only.
Verify actual file hashes, mobile selection, case entry, source handling, encryption/recovery, selected handoff, installability and complete pack reconstruction. Report connection and device checks actually performed. Do not claim a security audit, live private-repository/provider test or physical-phone installation that was not performed.

Artificial intelligence is a required product feature. Build and connect source-linked artificial intelligence summaries, explanations and legal research through the owner-controlled service, preserving payload review and source validation. The service code exists, but live operation requires actual private provider credentials, model and HTTPS hosting; do not describe an unconfigured connection as functioning artificial intelligence. Do not silently downgrade the artificial intelligence requirement to an optional future feature. Private MAYHEM build specifications are never included as hidden artificial intelligence context.

Artificial intelligence deployment includes a Node.js start path, a minimal service/Dockerfile, allowlisted .dockerignore, /healthz configuration-readiness endpoint and npm run check:ai authenticated no-case probe. Preserve the distinction between configured server settings and a verified live provider response. The workspace must reject unconfigured capabilities and clear a failed replacement connection. See service/README.txt for host settings and an explicitly approved synthetic-record provider check.

Selected handoffs: make protected export the primary handoff action and require review plus a confirmed handoff passphrase. Encrypt the selected ZIP using the existing authenticated vault/object format with the separate selected-handoff context. Keep case titles, original filenames and source revision inside ciphertext. Preserve an explicit readable-ZIP action. Include handoff.html and its reader/encryption modules in the complete pack and public offline cache. The recipient unlocks on the device without account, workspace connection or uploads, then deliberately downloads a readable ZIP. Test excluded-record isolation, original-byte preservation, passphrase mismatch/cancellation, wrong keys, tampering, a fresh recipient browser and cached offline use.

Navigation: preserve the same main menu, footer links and current-page marker across all eight public pages, including Psychological First Aid, along with sequential guide navigation. Public reading-position memory may store only public section IDs for the current installation/tab; never record private workspace contents, credentials or case identifiers there. Preserve workspace save/lock and unsaved-work protections. Cache the named public navigation pages/scripts and public instruction packs for offline access.

PSYCHOLOGICAL FIRST AID
Provide first-aid.html as a readable public page titled Psychological First Aid. Use full terms in its explanations and shared navigation. Include practical supportive first steps with primary sources, separate urgent crisis access and voluntary care, source-verified support cards, and distinct treatment-complaint and legal-order routes. Show the actual verification basis; directory listing does not establish endorsement or accreditation. No case intake, assessment or private-data transmission is required. Include the matching catalogue and public sources in the replication pack.

APPLICATION START
Installed ClarityPath launches Home at index.html. Keep the manifest identity and repository-relative scope stable when changing its starting page. The Open app action also opens Home; Open my workspace remains the explicit route into the workspace. Verify Home launch online and offline under the new owner’s repository path. The application also handles older installed Workspace launch addresses and Chrome on Android returning to an existing window. Preserve the runtime Home view and its Workspace resume behavior; a manifest setting alone does not cover those cases.

OLDER INSTALLED COPIES
Keep app/startup.mjs and the generated public app/home-view.mjs in the public shell and offline cache. An installed direct launch to the older workspace.html address returns to Home before workspace state initializes. Shared navigation marks deliberate Workspace entry with a temporary public routing parameter, consumed before normal use; public situation deep links remain available.
On an installed-app return or supported launch event, show the public Home content without unloading or serializing the current workspace. Open my workspace resumes its existing state and form contents. Public Home markup is generated from index.html, excludes installation controls within the already installed view, and contains no case records or scripts. Preserve file-picker and open-dialog continuity. Returning to Home is not a save, backup or recovery mechanism; fully closing still requires private saving or backup.
Verify the older launch address online/offline, repeated foreground returns with no native launch support, deliberate Workspace entry, original record preservation, unfinished form preservation, file-picker continuity, public deep links and ordinary browser access. Report simulated installed-mode checks separately from physical-phone verification.

GUIDED INSTALLATION
Home offers Set up my system, linking to workspace.html?view=installation. The workspace also exposes Installation. Preserve the six stages, Manual setup and With a coding assistant routes, concerns first, readable guide links, complete public copy/download, and a Next control that identifies the earliest unfinished action. Account creation and backend deployment still follow the complete directions under the owner's control.
Reuse the existing private repository, encryption, saving/loading, service, selected-request approval, encrypted backup and protected-handoff controls. Do not create sample cases or transmit a request merely by opening a step. Test material is explicitly created and selected by the operator.
Keep app/installation-state.mjs and app/installation.mjs in the exact pack and named public cache. Separate Verified this session, Owner confirmed and Prepared for download. Bind current saves, backups and handoffs to the workspace revision, bind repository checks to its verified identity, and reject stale service-response receipts. Starting a replacement check clears its earlier success. A prepared download does not prove a file was saved or opened.
The backup comparison decrypts and validates a chosen encrypted full-workspace backup locally, compares it with a current snapshot, rejects a changed workspace, and leaves current work untouched. Clear file and passphrase inputs afterward. Recipient handoff inspection and independent backup/recovery arrangements remain explicit owner confirmations.
Checklist progress remains in the open workspace session and resets on lock or refresh. Returning Home and choosing Set up my system must resume that session without unloading private work or unfinished forms. Verify this continuity and offline access to the public guided shell; connecting storage and a provider still needs their connections. Report controlled-service, browser-emulation and actual live-owner/phone checks accurately.

PRIVATE REPOSITORY CONTINUITY
The private repository remains the primary repository destination. Save privately must provide a connection/unlock action when no active connection is available, preserving current work. After explicit Remember private connection on this device, encrypt its settings under device protection. Clear unlocked secrets on lock, restore only after device unlock, verify the same private repository and encryption identity, and preserve the accepted remote revision so another device's changes cannot be overwritten. A cancelled merge must not authorise saving. Bind remembered settings to the actual installation address; cloning cannot inherit another owner's connection.
Keep remembered settings separate from case events, provider payloads, full-workspace backup and selected handoff. An independent backup and recovery check remain required. Report device-save failures accurately and preserve offline edits across reopening. Replication must include app/remembered-repository.mjs and tests/connection.test.mjs, the matching public cache and complete installation/recovery checks. These additions implement the storage and recovery requirements; they do not remove live storage, required artificial intelligence or recipient verification from installation completion.

BUILD OPTION THREE — WITH A TRUSTED PERSON
Provide three readable installation routes: manual work, a coding assistant, and a trusted person. Option three begins with the owner making their GitHub template copy or fork. The owner invites the builder temporarily into their public application repository, retains private credentials and account administration, completes the same required connections and recovery checks, demonstrates independent operation, and then removes temporary repository/host/provider access and replaces exposed setup secrets. Retain the complete trusted-person copy/download with shared up-front concerns and full technical manual. Mark handover and access removal as owner confirmations; ClarityPath does not send invitations, remove collaborators or verify access automatically. Removing collaboration does not recall public or downloaded copies. Include setup/trusted-builder-steps.txt and TRUSTED-BUILDER-SETUP.txt in the complete pack and the latter in the named public cache.
