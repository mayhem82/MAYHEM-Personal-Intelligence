CLARITYPATH — PUBLIC APPLICATION BUILD GUIDE
© 2026 Julian Minko · Architect of MAYHEM · ClarityPath

This guide describes the public ClarityPath application and its reproducible public files. Julian Minko’s supplied MAYHEM specifications are private build inputs. They are not included, licensed, offered for download or authorised for redistribution by this site or pack. Do not retrieve them from old commits, copies or caches. Do not add them to a source library or AI request.

## 0. Complete setup for the new owner
Read setup.html for both readable manual and AI routes. Put accounts, costs, permissions, privacy, recovery, device requirements and implementation limits first. Begin with GitHub account creation and optional coding-AI connection; distinguish that setup assistant from the required AI inside ClarityPath. AI-SETUP.txt and MANUAL-SETUP.txt are complete copy/download versions, each including the shared start-here material. Source documents are in setup/ and SETUP-FOR-NEW-OWNER.txt. Keep operating.html readable too.
When this repository or pack is supplied for cloning/installation, the receiving AI must carry out SETUP-FOR-NEW-OWNER.txt. It is a complete installation task: establish the recipient’s account and destination, create/use their own public application repository and a separate private case-data repository, deploy their site, configure encryption and independent recovery, deploy/connect required AI under their control, test the real authorised connections with synthetic data and publish the matching Build pack. Root AGENTS.md makes this task visible to coding agents working from a clone.
Use the source project as a reference. Configure the new owner’s actual Git remote, branch, Pages URL, service origin, endpoints and private credentials. Keep their case records and private settings out of the public site. Preserve the creator attribution. Complete independent work while any owner-controlled authentication, private credential entry or applicable charge approval is pending; identify the exact remaining blocker and keep installation marked incomplete until its required connections are genuinely verified.

## 1. Reproduce the public application
Use the exact public source files and image bytes in build-pack.txt. Text blocks are UTF-8 with LF line endings. Image blocks marked ENCODING: base64 must be decoded to bytes; the recorded hash and byte count refer to decoded bytes. The pack contains the working application, not a separate prefilled demonstration.
Preserve the creator notice, Disclaimer page, source attributions and public/private boundary. Installing for a different private-data owner does not transfer the creator’s attribution or rights in private MAYHEM material.
Run node scripts/package-release.mjs, then npm test. With the declared Playwright development dependency and a supported browser, run npm run test:e2e and npm run test:pwa. Package only the explicit public manifest. Do not upload workspace attachments, private build inputs, backups or credentials.

## 2. Public situations and sources
The initial page is a populated NSW situation catalogue, independent of saved private cases. It includes applicable Commonwealth-law reading sources. Provide Area of law and a complete Choose a situation dropdown directly beneath it. Search and area filters affect the entire dropdown, not only the paginated browsing cards. Choosing a situation displays its guide, topic reading links, bodies, contacts and sourced escalation information.
Keep official guide titles and attribution. Explain whether source text is included or opened at the external source. Preserve mandatory, conditional and direct routes, prior decisions/referrals/notices, evidence, timing, exemptions and source check dates. Do not invent a universal escalation ladder or claim complete coverage of all law.
The public legal source library contains public legal references only. Private product specifications must never appear there or become selectable case material.

## 3. Private workspace and required AI
The application records separate cases, original accounts and files, chronology, links, review, sources, summaries and selected handoffs. Keep original material and later interpretation separate. Corrections are additive. Preserve the implemented validation, case isolation, checksums and encryption behaviour when replicating.
Temporary in-memory work needs a save or download. Encrypted device saving, private GitHub storage and required AI assistance have separate setup. Use a private repository owned by the actual case owner, a restricted token and an encryption passphrase. Never put secrets or case data in the public repository, source pack or logs.
The AI service receives only the reviewed, selected payload. Do not append private specifications or unrelated project documents. Provider credentials stay on the owner-controlled server. Installation or a GitHub connection is not permission to transmit case data or private build material to an AI provider.
Do not change or reconstruct private MAYHEM definitions from memory. Work requiring private reference material must use it locally under its owner’s explicit authorisation; that authorisation does not permit publishing or transmitting it.

## 4. Installation, publishing and verification
Keep the supplied homepage logo, launcher icons, relative-scope manifest, standalone workspace launch and Install app control. Use a native install prompt where available and accurate manual instructions otherwise. Cache only the named public application resources; exclude private data, authenticated requests and external/API calls. Do not erase encrypted device data when updating public resources.
Publish the explicitly staged site/ output through the included Pages workflow. Before publication, verify that public files and pack contain no private specifications or extracts. Old restricted source paths must not return the original documents. Keep Build separate from the workspace; it contains this public application guide and public source only.
Verify actual file hashes, mobile selection, case entry, source handling, encryption/recovery, selected handoff, installability and complete pack reconstruction. Report connection and device checks actually performed. Do not claim a security audit, live private-repository/provider test or physical-phone installation that was not performed.

AI is a required product feature. Build and connect source-linked AI summaries, explanations and legal research through the owner-controlled service, preserving payload review and source validation. The service code exists, but live operation requires actual private provider credentials, model and HTTPS hosting; do not describe an unconfigured connection as functioning AI. Do not silently downgrade the AI requirement to an optional future feature. Private MAYHEM build specifications are never included as hidden AI context.

AI deployment includes a Node.js start path, a minimal service/Dockerfile, allowlisted .dockerignore, /healthz configuration-readiness endpoint and npm run check:ai authenticated no-case probe. Preserve the distinction between configured server settings and a verified live provider response. The workspace must reject unconfigured capabilities and clear a failed replacement connection. See service/README.txt for host settings and an explicitly approved synthetic-record provider check.

Selected handoffs: make protected export the primary handoff action and require review plus a confirmed handoff passphrase. Encrypt the selected ZIP using the existing authenticated vault/object format with the separate selected-handoff context. Keep case titles, original filenames and source revision inside ciphertext. Preserve an explicit readable-ZIP action. Include handoff.html and its reader/encryption modules in the complete pack and public offline cache. The recipient unlocks on the device without account, workspace connection or uploads, then deliberately downloads a readable ZIP. Test excluded-record isolation, original-byte preservation, passphrase mismatch/cancellation, wrong keys, tampering, a fresh recipient browser and cached offline use.
