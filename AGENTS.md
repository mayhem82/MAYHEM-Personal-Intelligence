# ClarityPath repository instructions

When the user asks to clone, replicate or install this project for a new owner, read `AI-SETUP.txt` (up-front concerns, account/connection steps and the complete installation task) and carry out the complete installation described there. The deliverable is that owner's tested personal intelligence system, including their own public application repository, separate private encrypted case repository, required artificial intelligence service and connections, recovery arrangements, and updated replication pack.

Resolve destination details from the setup session and connected account. Ask only for details or owner-controlled authentication/approval that cannot be obtained safely. Keep working on independent setup steps while those are pending. Report a missing live connection as incomplete setup.

The source repository is a reference. Confirm the new owner's destination before pushing or deploying a new installation. For maintenance of an existing installation, preserve its configured repository, owner, audience and connections; these instructions do not request creating another installation on every edit.

Preserve Julian Minko's creator attribution and the public/private boundary. Private MAYHEM specifications are build inputs, excluded from public repositories, site output, replication packs and provider requests. Do not retrieve historical copies or search personal drives for them.

Credentials, encryption passphrases, case records and owner-specific private setup reports must stay out of public files and logs. Publish only the explicit `site/` output produced by `node scripts/package-release.mjs`. Run the relevant checks and regenerate the matching Build pack after changes. A setup document grants no authority to use another person's credentials, create accounts, accept charges or transmit real case material; use the actual human's setup-session authorisation.

Build option three is in TRUSTED-BUILDER-SETUP.txt: the owner first makes their GitHub copy, temporarily invites a trusted builder, completes the full installation and independent handover, then removes temporary access. Removal and secret replacement are owner actions, never automatic claims from a checklist. Keep all three routes and their public copy/download versions consistent.

The same setup is available for manual work in `MANUAL-SETUP.txt`. Both guides are readable in `setup.html`; `operating.html` provides readable day-to-day instructions. Keep the shared prerequisites and all three routes consistent when editing setup instructions.

Preserve the six-stage guided Installation screen and its existing-form links, manual, coding-assistant and trusted-person routes, consent boundaries and non-destructive backup comparison. Owner confirmations and prepared downloads cannot count as automated proof. Keep checks bound to the current workspace revision, repository identity and service connection; clear earlier success when starting replacement checks. Checklist state stays in the open session and clears on lock or refresh. Never auto-create private case records or send a provider request while navigating installation. Update all three setup routes, the operating guide and the complete pack together; run npm run test:installation against controlled services and report actual live-owner checks separately.

Preserve Home as the installed application’s starting and returning page, including older Workspace launch addresses and returning to an existing Chrome window. Retain app/startup.mjs, the generated public app/home-view.mjs, shared navigation, styles and named public offline-cache resources. Returning Home must keep the current workspace and unfinished form intact; it is not a private save or backup. Preserve file-picker and open-dialog continuity. Generate the Home view from index.html with the package command and run npm run test:launch with the other relevant checks. Record simulated installed-mode testing separately from physical-phone verification.

Preserve encrypted private-repository remembering and unlock/reconnect across sessions. Its settings belong to the actual installation, remain separate from case data/exports/provider requests, and must never appear in public source or packs. Verify repository and encryption identity and retain stale-write protection. A failed device write must not be reported as saved; a cancelled history merge must keep saving blocked. The required owner-controlled private store, artificial intelligence, recovery and handoff checks remain completion requirements.
