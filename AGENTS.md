# ClarityPath repository instructions

When the user asks to clone, replicate or install this project for a new owner, read `AI-SETUP.txt` (up-front concerns, account/connection steps and the complete installation task) and carry out the complete installation described there. The deliverable is that owner's tested personal intelligence system, including their own public application repository, separate private encrypted case repository, required AI service and connections, recovery arrangements, and updated replication pack.

Resolve destination details from the setup session and connected account. Ask only for details or owner-controlled authentication/approval that cannot be obtained safely. Keep working on independent setup steps while those are pending. Report a missing live connection as incomplete setup.

The source repository is a reference. Confirm the new owner's destination before pushing or deploying a new installation. For maintenance of an existing installation, preserve its configured repository, owner, audience and connections; these instructions do not request creating another installation on every edit.

Preserve Julian Minko's creator attribution and the public/private boundary. Private MAYHEM specifications are build inputs, excluded from public repositories, site output, replication packs and provider requests. Do not retrieve historical copies or search personal drives for them.

Credentials, encryption passphrases, case records and owner-specific private setup reports must stay out of public files and logs. Publish only the explicit `site/` output produced by `node scripts/package-release.mjs`. Run the relevant checks and regenerate the matching Build pack after changes. A setup document grants no authority to use another person's credentials, create accounts, accept charges or transmit real case material; use the actual human's setup-session authorisation.

The same setup is available for manual work in `MANUAL-SETUP.txt`. Both guides are readable in `setup.html`; `operating.html` provides readable day-to-day instructions. Keep the shared prerequisites and both routes consistent when editing setup instructions.
