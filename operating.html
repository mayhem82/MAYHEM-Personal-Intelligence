Operating guide

Using your ClarityPath

Download operating guide text

START

  1. Launch ClarityPath to open Home. Choose Open my workspace or Workspace to continue. The public situation catalogue is available immediately; your private cases start empty.
  2. Returning to the installed app shows Home while retaining the current workspace and unfinished form in memory. Choose Open my workspace to resume. File selection and an open review dialog keep their current task.
  3. Home does not save work. Save privately, enable encrypted device saving or download an encrypted backup before fully closing the app. To update an older installed copy, save existing work and choose Home once before checking its launcher again.
  4. Choose Create situation, name the situation and add the jurisdiction if known, background and desired outcome. The form advances to State what you know after creation.
  5. Your saved cases lists your private situations. Use Create another situation or Create situation to add another. Cases remain isolated; the application starts without invented personal case records.

GUIDED INSTALLATION

Choose Set up my system on Home or Installation in the workspace. Choose Manual setup, With a coding assistant or With a trusted person, then follow Before you start, Your accounts and site, Private case storage, Required artificial intelligence, Backup and selected handoff, and Finish and review. Read accounts, costs, permissions, privacy and recovery first. Next names the earliest unfinished action; each stage links to the complete readable instructions. Copy and download contain public instructions only.

The screen reuses Storage & connections and Summaries & handoff. Return to installation brings you back from those forms. Creating a labelled test situation only fills the form until you submit it. Select invented test material yourself; a service connection sends no case content and a provider request still requires separate payload review and approval.

Verified this session identifies a successful application check. Owner confirmed identifies your confirmation of account control, test content, reopened originals, backup location, recovery or recipient checks. Prepared for download identifies an export action; check that its file was saved and opened independently. No confirmation substitutes for a missing connection or provider response.

Save privately, read the saved workspace and compare the reopened account and downloaded original. For a backup check, select the saved encrypted backup and its passphrase under Backup and selected handoff, then choose Verify backup without replacing work. This locally decrypts, validates and compares the file against current work; it does not import it. The passphrase and file selection clear after the check. Independently open the protected selected handoff using the reader and its separate passphrase.

The checklist lasts only for the current open session. Refreshing or locking starts a new checklist. Returning Home keeps it and the open workspace. A new record or draft requires a current private save, backup and handoff; a failed replacement check clears its earlier success. Save or back up current work before closing. This checklist is not an independent security audit or a durable installation report.

KEEP YOUR WORK

Temporary work stays in memory only. Under Storage & connections, enable encrypted device saving with a passphrase of at least 12 characters, download an encrypted backup, or connect an initialised private GitHub repository you own.

The static GitHub connection takes an expiring fine-grained token restricted to the private data repository, Contents read/write. Enter it in the password field; it stays in memory. Never put it in the public code or a message to an artificial intelligence. The application verifies the repository is private.

For a new private store, choose Initialise in the encryption form, then Save privately. For an existing store, choose Unlock and load. Only “Private save verified” indicates a confirmed remote save. A local encrypted copy is a separate thing.

If another device saved first, the application refuses to overwrite it. Preserve your encrypted backup, then use Preview merge with remote work. Both histories remain additive. Review the merge and any concurrent title changes before saving the merged work.

Choose Remember private connection on this device after connecting and unlocking the repository. If device protection is not enabled, enter and confirm a device passphrase. The repository address, restricted token and repository encryption passphrase are stored only inside an encrypted device envelope, separate from case records. After a refresh, full close or Lock / close, unlock saved work with the device passphrase; the app verifies and reconnects the same private repository without replacing current work. No repository request runs before that unlock. A forgotten device passphrase cannot be reset.

Save privately opens the existing repository connection or unlock form when needed. It keeps current work in place. Unlock for saving current work validates existing private work and asks you to review an additive merge where necessary. Cancelling that merge leaves saving blocked. Another device's newer remote revision must be reviewed before saving. Offline work can be kept encrypted on this device, then saved privately after reconnection. Device saving and repository saving have separate status messages; a failed device write is reported.

Disconnect GitHub clears the active connection for this session. Forget saved connection on this device removes remembered settings while retaining cases and repository files. A copied installation cannot reuse a remembered connection belonging to another site address. Encrypted backups and selected handoffs contain case work, excluding remembered credentials. Keep the token expiry current; renew it for the same private repository when required.

Keep a separate encrypted backup and its passphrase. Git history is not an independent backup. Lost passphrases cannot be reset by this site.

RECORD INFORMATION

Use State what you know. Enter original text and the source name or self-identified alias. Unknown and approximate dates are allowed. Certainty, additional corroboration and disagreement are distinct fields. A firsthand account is not rejected for lack of an attachment.

Original files are stored with byte digests, up to 25 MB each. Several files may belong to one record. They can be downloaded unchanged. A hash identifies bytes; it does not certify the truth of an event.

Connect related records using their selections. Correct earlier material by creating a new correction with a reason. The original remains.

To redact an account, create a separate redacted derivative and select that derivative for the handoff. It receives no original files automatically. Independently redact documents before adding them as separate derived attachments. Review all selected metadata and sources before sharing.

REVIEW AND ANALYSIS

Add what an item directly shows, its limits and questions. These notes do not change the source.

Record a Proof of Fact qualification only for the exact proposition and with an actual verification basis and authority. PF(H,E) is 0 or 1, never a confidence percentage. A directly stated self-identified account with preserved context and timestamp can qualify without institutional corroboration; do not assume every explanation in an account has thereby been independently verified.

The evidence-freeze form records an actual authorised instruction and creates a snapshot. Subsequent records form additions; the existing snapshot is retained.

Add the relevant authorised DFAPTA output as a separate analysis record linked to its frozen snapshot. Working review and Internal Cognitive Sandbox material are different types and cannot be selected as authorised DFAPTA engine input merely by writing a hypothesis.

This release records operator-provided qualification and analysis provenance. It does not invent an automated Factual Strength formula or certify the operator's authority.

LEGAL SOURCES

Add the exact source passage, direct URL, provision/paragraph, jurisdiction, version/effective date and relevance to the private case. Record who checked it. Legal instrument applicability is separate from the fact that a URL exists.

Do not assume this library contains every law relevant to an unknown case. Missing legal text stays a visible gap. The configured research service can retrieve source-backed information after you approve the request; you can also add source text yourself without an application programming interface.

SOLICITORS ADVOCATE ENGINE

Activate the named engine for the selected case, specifying jurisdiction, target recipient/body, purpose, actual activation authority, frozen evidence snapshot and relevant authorised DFAPTA outputs.

1. Map the obligation: select a checked legislative passage, identify the duty holder, required action, timing, applicability and verified evidence propositions.

2. Assess exposure: select that obligation and verified outcome propositions, then record whether the documented gap is present or absent and explain the comparison. Missing material blocks assessment rather than becoming a probability score.

3. Frame the submission: supply the actual recipient's jurisdictional basis and requirements and requested outcome. The application produces a source-linked draft with the named recipient, obligations, assessments and evidence propositions. Review the draft. Downloading it sends nothing.

SUMMARIES AND HANDOFF

Choose records and case sources explicitly. Create structured summary works without an artificial intelligence service. It preserves original accounts, date precision, classifications, review and source references.

Preview protected handoff is the primary handoff action. Review the selected records and sources, case background, desired outcome and originals, then enter and confirm a separate passphrase of at least 12 characters. The download is an encrypted JSON envelope holding only the selected ZIP and its exact source revision. The supported ZIP size is up to 200 MB; export fewer files if needed. Keep the passphrase separately. An encrypted full-workspace backup is a different export.

Give the recipient the protected file and the site's handoff.html link; share the passphrase through a separate channel. The unlock page needs no account or private repository connection. It decrypts locally, uploads nothing and clears the entered passphrase. After unlocking, the recipient explicitly downloads a readable ZIP, extracts it and opens index.html. The ZIP includes the selected summary, source indexes, originals, eligible submission drafts and SHA-256 manifest. Once downloaded, the readable ZIP must be kept privately. Clear unlocked package releases the page's unlocked copy; it does not remove saved downloads.

Preview readable handoff is also available as an explicit choice with a clear disclosure. Its ZIP is not encrypted. Nothing is emailed, lodged or published by creating either handoff. Installed public-shell caching includes the recipient page, which works offline after it has been cached; first-time visitors need to load the page and its scripts.

REQUIRED ARTIFICIAL INTELLIGENCE SERVICE

Run the included service under your own account using service/README.txt. Put its provider key only in server-side secrets. GitHub Pages itself cannot run that server.

Connect its HTTPS endpoint and service access key in the workspace. For a narrative or research request, select the records/sources, enter the question and review the exact JSON payload and provider/model before approving transmission. Attachments and unselected material are not automatically sent.

The connection checks server configuration and rejects missing provider settings. It sends no case data and makes no provider call. Verify an actual provider response separately with an explicitly approved synthetic record before relying on live artificial intelligence. Deployment health checks and the no-case command npm run check:ai are described in service/README.txt.

Generated output is a separate unreviewed draft. Check the direct links, selected case references, source versions and applicability. Provider web citations are clickable; missing/unknown selected-case citations are rejected. A failed provider request does not change the original records.

No paid provider call or private GitHub account is configured by this public release. These need the actual owner's settings. Never describe them as live-verified before a real authorised connection test succeeds.

BUILD AND REPLICATION

Supply the complete Build pack or cloned public repository to the receiving artificial intelligence. AGENTS.md and AI-SETUP.txt direct it to finish the recipient’s own personal intelligence installation: their new public application repository, distinct private case repository, encrypted storage and recovery, required artificial intelligence hosting/connections, live synthetic-data checks and updated replication pack. The source owner’s account, site origin and services must not become the recipient’s destinations. The owner retains control of authentication and private credential entry. Any unresolved connection or implementation gap remains explicit. The receiving artificial intelligence must not search OneDrive or personal drives for missing instructions.

NEW SOUTH WALES SITUATIONS AND ESCALATION

Start with What is your situation? Browse or search the populated public catalogue without creating a case. Read the selected official guide, topic instruments, body/contact links and escalation prerequisites. Save a copy with Download this situation and pathway sources. Use this situation for a private case pre-fills a case form; nothing is created until you submit. Your saved cases is a separate selector.

Pathways distinguish mandatory, conditional and direct routes. Check the decision/order-specific deadline and exception in the linked official source. An ordinary complaint does not automatically stop another filing deadline. Full external legal source text is read at its source.

INSTALL CLARITYPATH

Choose Install app on the homepage. Where the browser provides an installation prompt, accept it there. Otherwise follow the displayed browser-menu instructions; on iPhone/iPad use Safari, Share, Add to Home Screen. Installed launch and return open Home. Choose Open my workspace to enter or resume the workspace. Installation does not connect private storage or send case data. Public application files can work offline after caching; external source reading, GitHub saving and artificial intelligence assistance still need their respective connections. Protect unsaved work and set up encrypted storage as described above.

SITE NAVIGATION

The same Home, Psychological First Aid, Workspace, Setup, Guide, Build, Handoff and Disclaimer links appear on each main page. The current page is marked. Guide sections have previous/next links. This tab remembers only the last section read in public guides; choosing the current page in the menu or Back to top returns to its beginning. Workspace saving and unsaved-work warnings remain separate from this public reading position.

PSYCHOLOGICAL FIRST AID

Open Psychological First Aid from the main navigation for practical first steps and verified support. Choose what is happening, then the kind of support wanted. Every service shows access, costs, hours, operator, source and check date. Contact a service only by choosing its link. No private case is required. For treatment concerns and legal orders, continue to the mental health situations and check the order-specific process with an adviser.

BUILD WITH A TRUSTED PERSON

Build option three begins with the owner making their application copy using GitHub. The owner then invites the trusted builder temporarily, completes the same private storage, required artificial intelligence, recovery and handoff checks, and demonstrates independent operation. After handover the owner removes temporary repository and hosting/provider access and replaces any secrets the builder could access. Public source remains public; removal cannot recall copies. The Installation screen labels independent operation and access removal as owner confirmations. Full instructions are in setup.html#trusted-builder-setup and TRUSTED-BUILDER-SETUP.txt.
